# VacDepoctrl agent instructions

## Scope and safety

Aryan has an electronics/hardware background. Keep changes scoped to the task.
Ground claims in current tool results; documentation is not proof of live state.
This repository controls vacuum equipment, valves, gas flow and sputtering power.
Never launch/restart the real controller, toggle GPIO, scan/write hardware buses,
flash/run ESP32 firmware, reboot the Pi or change outputs autonomously. Hand the
run step to Aryan unless he explicitly authorizes that action in the current task.
Authorization for a previous bench run is not standing authorization for later work.
Hardware-free tests, static checks, source edits and read-only OS/log inspection
are allowed. Do not import main.py for inspection: it initializes hardware at
module scope, and can automatically enter PUMP_DOWN and READY at startup.

## Before edits

Run `git status --short --branch`, `git log -1 --oneline` and `git remote -v`
in the checkout you will modify. Inspect both checkouts if transferring work.
The Pi and Mac are separate working copies, not an automatically synchronized
folder. Check for deployment edits on the Pi and untracked work on the Mac
(including the existing `firmware/` directory) before synchronizing.
Preserve user changes. Do not use blanket rsync,
reset, clean, or pull over a dirty checkout. Transfer reviewed changes explicitly;
do not transfer venvs, logs, lock files, credentials, or boot configuration.
Keep work in Git and commit/push only within the user's authorized scope.

## Hardware-free verification

On the Pi, from `/home/av/VacDepoctrl`:

```sh
PYTHONDONTWRITEBYTECODE=1 ./venv/bin/python -m unittest discover tests/unit -q
bash -n scripts/setup.sh
git diff --check
```

On the Mac, the unit suite can use `python3` instead. The suite installs fake
hardware before loading drivers and does not import main.py. Never run broad
discovery across `tests/`: sibling ADC, DAC, opto and valve scripts access real
hardware. Simulation uses `SPUTTER_SIM=1`, but inspect its startup first; do not
run it alongside the live controller in the same checkout (shared instance lock).

## Deployment facts (verify live when relevant)

- Raspberry Pi 5, Debian 13; Tkinter GUI plus web dashboard on port 8080.
- Hardware I2C1: SDA GPIO2 / physical pin 3; SCL GPIO3 / physical pin 5.
- `config.py`: `I2C_BUS_NUMBER = 1`; ADS1115 at 0x48; MCP4725 at 0x60.
- Boot settings: `dtparam=i2c_arm=on`, `dtparam=i2c_arm_baudrate=100000`.
- `/boot/firmware/config.txt.before-vacdepo-i2c1` is the pre-change boot backup.
- `rpi-lgpio` provides the existing `RPi.GPIO` imports on Pi 5. Do not install
  legacy RPi.GPIO alongside it. Blinka 9.2.0 declares the old package dependency;
  setup replaces it afterward. A known `pip check` metadata complaint remains.
- Main event log: `/home/av/VacDepoctrl/sputter_ctrl.log`.
- Last manual background launch output: `/home/av/vacdepo-launch.log`.
- Desktop launcher: `/home/av/Desktop/VacDepoctrl.desktop`, generated by setup.
- No managed controller service was established. Check processes before launching;
  never launch a second controller or kill the current one merely to run tests.
- Useful read-only checks: `pgrep -af '[m]ain.py'`, `ls -l /dev/i2c*`,
  `tail -50 sputter_ctrl.log`, `vcgencmd measure_temp`, `vcgencmd get_throttled`.
- Passing startup self-test means ADC/DAC acknowledged I2C addresses, not that
  analog values, calibration, power cutoff, or physical equipment are validated.

## ESP32 autotransformer work

This is currently planning only. Do not infer permission to implement or operate
it from the access setup. First establish motor/driver, limits, isolated voltage
feedback, independent power cutoff, existing firmware, and desired operation.
Stopping the motor does not remove the autotransformer's output voltage.
